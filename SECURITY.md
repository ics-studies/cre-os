# Security Policy

## Reporting a vulnerability

Report security issues privately to **members@ics-studies.org**. Do not open a
public issue for a vulnerability that could expose credentials, customer data,
tenant boundaries, document contents or an unpatched attack path.

Please include:

- the affected repository, release and component;
- a concise reproduction;
- the likely impact and affected data;
- whether the issue is already public; and
- a safe contact method for follow-up.

## Scope

Security reports are welcome for source code, local services, hosted API
components, MCP adapters and release artifacts. The following are not accepted:

- requests for harmful biological, cyber, weapon or evasion capability;
- testing against customer accounts or data without authorization;
- denial-of-service tests against production;
- social engineering;
- reports based only on a scanner banner without a reproducible impact.

## Disclosure

We will acknowledge a complete report, triage it and coordinate remediation and
disclosure where appropriate. Never include an API key or sensitive customer
document in a report.
