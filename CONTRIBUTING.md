# Contributing

Thank you for evaluating or contributing to an ICS project.

## Before opening a pull request

- open an issue for a material design change;
- keep changes scoped to the stated problem;
- preserve the repository's product and claim boundaries;
- use English for public documentation;
- do not include customer data, secrets or unpublished manuscripts; and
- add or update tests for behavior changes.

## Pull requests

A useful pull request states:

1. the problem;
2. the chosen approach and rejected alternatives;
3. compatibility, licensing and security effects;
4. tests and manual verification; and
5. any remaining limitation.

By contributing, you agree that your contribution can be distributed under the
licence of the receiving repository. Sign-off uses the Developer Certificate of
Origin.

## Confidential material

Do not submit:

- credentials, API keys or cookies;
- customer reports or contracts;
- unpublished book manuscripts;
- calibrated held-out test data;
- sensitive operational interfaces; or
- harmful dual-use instructions.

Security issues should follow [SECURITY.md](SECURITY.md).
